# 이미지에서 시작하는 라이브러리

이미지 작업실 상단의 **앱 언어**에서 영어·한국어·일본어를 바꿉니다. 선택 사례·비교 후보·편집 초안과 원문은 유지합니다. [언어 설정](LOCALES.md).

이미지를 넣고 **비슷한 사례 → 실제 작가 태그 → 기록된 프롬프트·생성 조건**으로 이동합니다. 질의 이미지에 프롬프트나 메타데이터가 없어도 검색합니다. 단독 작가도 하나의 조합으로 다룹니다.

## 사용 방법

1. 앱의 **이미지 작업실**를 누릅니다.
2. **검색 방식 · 라이브러리 관리**에서 폴더의 전체 경로를 한 줄에 하나씩 입력합니다. **폴더 가져오기**는 하위 폴더까지 PNG/JPEG/WebP를 탐색합니다. **라이브러리 총 등록 수에는 제한이 없습니다.** 파일은 순차 등록하고 목록은 페이지 단위로 조회합니다. **앱 생성 이력 연결**은 앱 manifest를 연결합니다. 라이브러리 조회 중에도 새 앱 이력이 주기적으로 동기화됩니다.
3. 파일을 선택하거나 이미지 파일을 검색 영역에 놓습니다. 등록된 사례에서는 **이 그림과 비슷한 사례**를 누릅니다. 같은 픽셀의 질의 이미지·사본은 결과에서 제외됩니다.
4. 사례를 선택하면 실제 기록을 볼 수 있습니다. 작가 조합 버튼은 같은 태그 순서·가중치·사용 모델을 가진 사례로 이동합니다. **작가 태그만 덧붙이기**, **프롬프트 가져오기**, **조건까지 가져오기** 중 필요한 범위를 선택하면 **03 프롬프트** 초안으로 가져옵니다. 내용을 다듬고 **생성 화면에 적용**을 누릅니다. 이 동작도 생성 요청을 보내지 않습니다.
5. 태그·컬렉션·메모·즐겨찾기를 저장하고 텍스트로 검색할 수 있습니다. 유사사례에는 **닮았음 / 안 닮았음 / 조건을 다시 쓰고 싶음** 평가를 남깁니다. **기준 그림 다시 검색**을 누르면 닮음 판단을 반영한 결과를 봅니다. **닮음 평가 초기화**로 해당 사례의 닮음 평가를 되돌릴 수 있습니다.
6. 기본 정렬은 **닮은 순서**입니다. 비슷한 구도가 계속 나오면 **다양한 사례 섞기**를 선택하고 **기준 그림 다시 검색**을 누릅니다. 가까운 후보 중 서로 다른 그림을 섞으며, 검색 기준은 이미지 픽셀입니다.

프롬프트 적용은 긍정·부정 프롬프트만 바꾸며 현재 제공자와 모델을 유지합니다. 전체 조건 적용은 기존 프리셋 적용 경로를 사용하고 현재 Opus 무료 한도를 유지합니다. 누락된 모델·참조 파일·기타 조건은 자동 복원되지 않으므로 생성 전에 확인해야 합니다. A1111 설정은 원문 보존 및 프롬프트 적용까지만 지원합니다. 일반 ComfyUI workflow 그래프 해석은 아직 지원하지 않습니다.

## 검색과 VRS의 범위

| 방식 | 준비 | 의미 |
|---|---|---|
| 색감·배치·윤곽 검색 | 기본 CPU 처리 | 색·공간 배치·윤곽을 합친 고정 특징의 코사인 유사도 |
| VRS 이미지 검색 | 앱 내장 인코더 코드 + 준비 화면에서 받는 Gemma 4 비전 가중치 | RGB 픽셀에서 얻은 임베딩의 코사인 유사도 |

VRS 벡터가 하나 이상 준비되면 VRS 검색을 기본 선택합니다. 사용자가 검색 방식을 바꾸면 그 선택을 유지합니다. VRS 특징 추출에는 등록 이미지나 업로드 이미지의 RGB PNG만 전달합니다. 프롬프트·파일명·작가 태그를 검색 특징으로 쓰지 않습니다. 메타데이터는 검색한 사례에 연결된 기록으로만 보여 줍니다.

SWEGCA Architecture의 근거 누적 코어를 내장하여 검색과 명시적 평가 처리에서 호출합니다. 평가의 최신 상태를 재생하고 판정 영수증을 저장합니다. 사례와 평가를 로컬에 축적하며, 유사도는 작가의 신원이나 실제 화풍 일치 확률을 뜻하지 않습니다.

**닮았음 / 안 닮았음**과 **A / B가 더 닮음**은 같은 픽셀의 기준 그림·같은 인코더로 다시 검색할 때 순서에 반영됩니다. 가까운 후보 사이에서만 작은 보정을 적용하고, 표시하는 코사인 유사도는 그대로 유지합니다. 반복해서 눌러도 중복 누적하지 않습니다. **조건을 다시 쓰고 싶음**은 닮음 순서를 바꾸지 않으며, **둘 다 비슷함 / 둘 다 다름 / 판단 보류**는 상대적인 우열을 부여하지 않습니다. 개인의 선호에 따른 순서 보정은 SWEGCA의 근거 판정과 구분되며 코어 임계값을 바꾸지 않습니다.

외부 그림을 연속 검색하면 인코더를 최대 60초 동안 실행 PC의 메모리에 유지하여 재사용합니다. 생성이나 다른 GPU 작업이 시작되면 대기 중인 인코더를 먼저 종료하고, 사용하지 않으면 자동으로 비웁니다. 색인 벡터는 실행 PC의 메모리에 캐시하고 가져오기·벡터 변경 시 갱신합니다. 앱 재실행 직후나 인코더가 비워진 뒤의 첫 외부 검색은 준비 시간이 추가됩니다.

명시적인 `artist:` 태그만 분리하며 작가 이름을 그림에서 추정하지 않습니다. 순서·가중치가 같은 조합도 모델이 다르면 탐색에서 구분합니다. 통계에는 작가 태그 조합 수와 모델별 조합 수를 따로 표시합니다. 원문 프롬프트는 별도 보존합니다.

## 이미지 검색 준비

1. 상단 **연결 · 준비 → 비슷한 그림 찾기 → 이미지 인코더 준비**를 누릅니다. 약 320 MiB의 고정 버전 비전 가중치와 필요한 실행 패키지를 앱 모델 폴더에 준비합니다. 모델 파일 해시를 검증합니다.
2. 라이브러리에서 폴더를 가져온 뒤 **등록 이미지 색인 만들기**를 누릅니다. CUDA GPU가 필요합니다. GPU가 없으면 기본 CPU 검색을 사용합니다.
3. 8장씩 저장하고 진행합니다. 취소해도 저장된 벡터가 남으며 다시 누르면 남은 그림을 처리합니다. 이미 색인된 그림은 전체 작업 완료 전에도 검색할 수 있습니다.
4. 문제가 있으면 **파일별 문제 확인**에서 원본 누락·읽기 오류·인코더 오류를 구분해 봅니다. 사라진 원본은 건너뛰며 나머지는 계속 처리합니다. 원본을 복구한 후 색인을 재시도하세요.

외부 VRS 저장소·별도 Python 환경·`ANIMA_LIBRARY_VRS_*` 변수는 필요하지 않습니다. 기존 버전의 벡터는 삭제하지 않고 별도 계약으로 보존합니다. 코드·전처리·가중치·주요 실행 패키지가 달라지면 새 색인을 만들며 서로 다른 계약을 섞어 비교하지 않습니다.

## 외부 이미지와 생성 정보 정제

캡션 작업은 필요하지 않습니다. 이미지를 RGB 픽셀로 읽는 경로와 생성 정보를 읽는 경로를 분리합니다. 손상된 JSON·필드 형식·비정상 수치를 정제하고, 복구 가능한 프롬프트는 보존합니다. 읽을 수 없는 생성 정보는 경고로 남기고 픽셀 등록·검색을 계속합니다. 없는 작가 태그나 캡션을 추측해서 넣지 않습니다.

동일 픽셀의 서로 다른 파일은 결과 카드 하나로 묶고, 연결된 모든 생성 기록·원본 위치를 상세 화면에서 선택합니다. 가져오는 기록은 원래 파일의 정확한 기록으로 연결됩니다.

## 보관과 출처

- DB와 특징은 `outputs/library/library.sqlite3`, 썸네일은 `outputs/library/thumbnails`에 저장합니다. 원본은 경로로 참조하고 덮어쓰지 않습니다.
- SHA-256이 같은 파일은 하나로 연결하고 서로 다른 생성 기록은 함께 보존합니다. 픽셀이 같은 파일의 메타데이터가 다르면 별도 등록될 수 있지만 검색에서는 중복을 제외합니다.
- 게시물별 폴더에 `source.json`을 두고 `{"post":"https://example.org/post/123"}`를 기록하면 사례의 **원본 위치 · 출처**에 출처 링크가 표시됩니다. URL은 처음 가져올 때 읽습니다. 자격 증명·로그인 쿠키는 저장하지 않습니다.
- 개인 이미지·프롬프트·특징·검색·평가 자료는 Git 제외 대상인 `outputs`에만 둡니다. 공개 코드·문서에는 개인 원문을 넣지 않습니다.
- 현재 기능은 신뢰할 수 있는 로컬 사용자를 위한 기능입니다. 기존 서버의 요청 출처 검사 아래에서 제공되며 로컬 폴더 가져오기와 기록 조회 권한을 갖습니다. 서버를 인터넷에 공개하는 용도로 설계하지 않았습니다.

## 검증과 검색 품질

합성 이미지 테스트는 업로드·중복 제외·기록 연결·선택적 재사용·비교와 취소를 확인합니다. 이 검사는 화풍 검색의 정답률을 뜻하지 않습니다. 검색 품질은 질의 그림과 같은 파일/변형본을 제외하고, 출처 게시글까지 분리한 평가 자료로 따로 검토해야 합니다. 후보의 장면·머리색·구도와 화풍의 유사성도 구분해서 평가하세요.

[현재 통합 검증 범위](MAIN_UPDATE_2026-10-14.md)를 참고하세요. 사용자 이미지·프롬프트·사례별 검색 결과·수집 통계와 개인 평가 보고서는 공개 문서에 포함하지 않습니다.

## 이미지 작업실 UI, 2026-10-14

독립 시안의 탐색 흐름을 실제 앱에 연결했습니다. **이미지 작업실**는 화면 전체를 쓰는 작업실을 엽니다.

- 왼쪽에는 검색 기준 그림이 남습니다. 업로드·드롭 또는 등록 사례의 **이 그림과 비슷한 사례**로 검색할 수 있습니다.
- **01 탐색**은 전체 그림을 자르지 않는 갤러리, 카드 크기 선택, 텍스트·즐겨찾기 필터, 48장 단위 더 보기를 제공합니다. 긴 작가 목록은 카드에서 요약하고 오른쪽 상세에서 원문을 확인합니다.
- 검색에 나타난 작가 조합을 펼쳐 같은 순서·가중치·모델의 사례로 이동한 뒤 **유사사례로 돌아가기**로 기준 그림의 검색 결과를 복원합니다.
- 오른쪽 패널에서 기록 선택, 작가 순서·가중치, 프롬프트, 모델·시드, 생성 조건, 출처, 태그·컬렉션·메모를 확인·관리합니다. 이미지 클릭은 최대 1,600px 미리보기를 엽니다. 원본이 사라지거나 변경되면 보관된 썸네일을 사용하고 대체 표시를 합니다.
- **02 비교**에서는 같은 검색의 후보 두 장을 기준 그림과 비교합니다. 자동으로 순위 인접 쌍을 보여주거나 탐색에서 **비교에 담기**로 직접 두 장을 선택합니다. A / B / 둘 다 비슷함 / 둘 다 다름 / 판단 보류를 저장하고 **마지막 판단 취소**로 되돌립니다. 상대 비교는 기존의 닮음·재사용 평가와 분리됩니다.
- **03 프롬프트**는 생성 폼과 분리된 편집 초안입니다. 가져오기 전 수동 작성 내용까지 되돌릴 수 있고, 탭 이동·작업실 닫기/다시 열기에도 미적용 초안이 유지됩니다. 프롬프트만 가져오기를 선택하면 이전에 가져온 생성 조건은 제거됩니다. 같은 브라우저·앱 주소의 저장소에 초안과 최근 가져오기 되돌리기 10개를 저장하므로 새로고침 후에도 복원됩니다. 브라우저 저장소를 삭제하거나 시크릿 세션을 종료하면 유지되지 않을 수 있습니다.
- 작가 조합을 덧붙일 때 원래 초안과 들어오는 조합의 가중치 표기를 먼저 맞춥니다. 생성 엔진을 바꿀 때의 최종 변환은 [생성 작업실](GENERATION_WORKSPACE_KO.md)의 설정을 따릅니다. 가져온 이미지·생성 기록·가져오기 범위가 참고 사례로 연결되고 생성 결과에서도 해당 기록으로 돌아갈 수 있습니다. 이 연결은 작가 판정이나 자동 학습이 아닙니다.
- 하단에 현재 작업 메시지와 생성 진행이 유지됩니다. 작은 화면에서는 기준 그림을 상단에 고정하고 상세를 갤러리 아래에 배치합니다. 데스크톱에서 입력창 밖의 좌우 방향키로 사례를 넘길 수 있습니다.

비교 기록은 SQLite `comparisons`에 검색 ID, 두 사례 ID, 판단, 시각, 취소 여부로 저장됩니다. 재시작 후에도 평가와 순서 보정은 유지되지만 화면의 비교 진행·취소 스택은 현재 검색 세션에만 존재합니다. **마지막 판단 취소** 후 다시 검색하면 그 판단의 보정도 취소됩니다. 같은 두 후보를 여러 번 비교하면 최신의 취소되지 않은 판단을 사용합니다. 가져온 사례의 정확한 생성 기록과 적용 범위는 새 결과에 연결됩니다.

브라우저 검사는 임시 합성 자료와 헤드리스 Chromium으로 수행하며 완료 후 브라우저를 닫습니다. 개인 이미지나 실제 NAI 호출 없이 UI와 저장 동작을 검사합니다. [검증 재현 명령](APP_REFERENCE.md#verification-and-publication-boundary)을 참고하세요.
