# NovelAI 생성 / 인페인트 엔진

Anima APP 0.5.0은 로컬 Anima와 NovelAI 생성·인페인트를 같은 GUI, 서버 큐, 설정 프리셋, 히스토리에서 사용합니다. 기본 엔진은 로컬 Anima입니다. NovelAI를 선택하면 프롬프트가 외부 NovelAI 서비스로 전송되며, 인페인트에는 입력 이미지와 마스크도 전송됩니다.

## 설정과 실행

서버를 실행할 환경에서 `NAI_ACCESS_TOKEN`을 설정하세요. 기존 `NAI_API_TOKEN`도 호환용으로 사용할 수 있으며, 둘 다 있으면 `NAI_ACCESS_TOKEN`이 우선합니다. 토큰은 서버에서만 읽습니다. 앱은 이메일/비밀번호 로그인이나 브라우저 토큰 입력·저장을 구현하지 않습니다.

서버를 시작하고 화면 상단의 `생성 엔진`에서 NovelAI를 선택하세요. T2I, Img2Img, 일반 / Focused 인페인트,
기존 이미지 자동 디테일러를 선택하고 NAI 전용 참조·캐릭터·보정 설정을 사용합니다.
로컬 모델·LoRA·VRAM·업스케일 설정은 로컬 엔진용입니다.

`GET /api/nai/status`는 `{configured, source, variable}`만 반환합니다. `GET /api/providers`에는 엔진별 기능과 요청 한도가 있습니다. 토큰이 없으면 GUI의 NovelAI 생성 버튼은 비활성화되고, 실제 큐 등록은 `409 nai_token_missing`으로 거절됩니다. `serve --dry-run-default`에서는 토큰과 네트워크 요청 없이 설정·manifest 경로를 확인할 수 있습니다.

## 기존 NAI 이미지에서 생성 조건 불러오기

프롬프트 패널의 **이미지에서 생성 조건 불러오기**에 원본 PNG/WebP를 선택하거나 드래그하세요.
프롬프트, 네거티브, 크기, 스텝, CFG, 시드, 샘플러, 스케줄러, CFG rescale,
Brownian 및 앱이 표현할 수 있는 Variety boost를 미리 확인하고 **생성 조건 적용**을 누릅니다.
적용하면 NovelAI 엔진으로 전환하며, 생성은 별도로 생성하기를 눌러야 시작됩니다.

`Comment.model_hash`와 `Source` 끝의 해시로 모델을 구분합니다. 예를 들어 V5의
`DB276663`은 Curated, `0ADF9AB7` / `657484A5`는 Full입니다. 대응표는
[NovelAI 웹의 공개 코드](https://novelai.net/_next/static/chunks/pages/_app-b1c0ffe38c343809.js)를
2026-10-09에 확인했습니다. 웹은 일부 오래된 V4 해시를 V4.5 Curated로 연결하지만,
이 앱은 원본 표기가 V4인 경우 자동으로 버전을 바꾸지 않고 수동 확인을 요구합니다.
모르는 해시, 앱에서 지원하지 않는 모델,
해시/모델 ID가 서로 다른 경우에는 자동 추정하지 않고 모델 선택을 요구합니다.
모델을 직접 바꾸는 것도 가능합니다. 메타데이터를 읽는 작업은 생성 서명 검증은 아닙니다.

인페인트 모델의 해시는 일반 생성 모델과 구분해서 취급합니다. 웹의 대응표가 일부 해시를
같은 계열로 묶기 때문에 해시만으로 생성 방식까지 단정하지 않습니다. `request_type`의
`PromptGenerateRequest` / `Img2ImgRequest` / `NativeInfillingRequest`와 명시적
`-inpainting` 모델 ID도 확인하고, 원본 해시·인식한 모델·원본 생성 방식을 따로 표시합니다.
인페인트 원본은 **인페인트 조건 적용**으로 생성 방식·전용 모델·기록된 강도를 복원합니다.
원래 입력 이미지와 마스크는 생성 결과에 포함되지 않으므로 기존 선택을 지우고 다시 지정해야 합니다.
I2I 원본은 **Img2Img 조건 적용**으로 모델·강도·추가 노이즈를 복원합니다. 입력 이미지는 다시 지정합니다.
실행 목록에 없는 전용 모델은 원본 모델명을 표시하고 수동 선택을 요구합니다.
`1229B44F` 등 계열만 확인되는 변형 해시는 생성 방식 기록이 없으면 수동 확인을 요구합니다.

PNG 텍스트, WebP EXIF와 알파 채널 `stealth_pngcomp`를 읽습니다.
[NovelAI의 공식 메타데이터 도구](https://github.com/NovelAI/novelai-image-metadata)를
형식 확인에 사용했습니다. 파일은 참조 이미지 업로드와 같은 크기 제한, 최대 16메가픽셀,
압축 해제된 메타데이터 1MiB 제한으로 검사하며 임시 파일은 읽은 뒤 제거합니다.
`POST /api/metadata/novelai`는 원본 이미지 바이트를 받아 폼에 적용 가능한 필드와 경고만
반환합니다. 토큰은 필요하지 않고 생성 큐나 외부 API를 호출하지 않습니다.

Vibe, Precise Reference, SMEA/DYN, 이미지 입력 등 지원되지 않는
조건은 경고로 표시합니다. 누락되거나 범위를 벗어난 필드는 현재 폼 값을 유지합니다.
Opus 요청 한도도 현재 설정을 유지하므로 생성 전에 **전송 설정**의 크기와 스텝을 확인하세요.
메타데이터가 제거된 이미지에서는 생성 조건을 복원할 수 없습니다.

## 캐릭터별 프롬프트와 좌표

NovelAI 설정의 **캐릭터별 프롬프트와 위치**를 펼쳐 최대 5명을 추가합니다.
캐릭터마다 프롬프트·네거티브·X/Y를 따로 입력하며, X는 왼쪽 0에서 오른쪽 1,
Y는 위 0에서 아래 1입니다. **캐릭터 위치 지정**을 끄면 좌표를 저장하되 요청의
`use_coords`는 false이고, **캐릭터 순서 사용**으로 `use_order`를 선택합니다.
V4/V5의 T2I와 인페인트에서 지원하며 V3에 캐릭터를 지정하면 전송 전에 거절합니다.
기존 ComfyUI 노드처럼 양성·음성 캡션의 순서와 중심점을 맞춰 전달합니다.

큐·프리셋·manifest·히스토리는 캐릭터 설정을 보존합니다. 캐릭터 프롬프트와
네거티브의 와일드카드도 전송 전에 확장하고 원문과 선택 이력을 저장합니다.
PNG/WebP 가져오기는 V4 캡션의 최대 5명, 캐릭터당 중심점 1개를 복원합니다.
5명 초과·여러 중심점·좌표 불일치·잘못된 값은 부분 복원하지 않고 경고하며,
캐릭터 목록을 비워 이전 설정이 섞이지 않도록 합니다. 캐릭터가 없는 이미지도
이전 캐릭터 목록을 비웁니다. 합성 인페인트 PNG에도 캐릭터 캡션을 기록합니다.

## 가중치 문법 변환

프롬프트 패널의 **프롬프트 가중치 문법 변환**에서 공통 또는 캐릭터별 프롬프트를
고르고 ComfyUI, NAI V4/V5, 구형 NAI 사이의 여섯 방향으로 변환합니다.
**변환 미리보기**는 원문과 결과를 보여주고, **선택한 프롬프트에 적용**을 눌러야
폼이 변경됩니다. 원문·적용 대상·문법이 바뀌면 미리보기를 다시 해야 합니다.
변환은 로컬에서 수행하고 모델이나 생성 엔진을 바꾸지 않으며 생성 요청도 없습니다.

`converters.py`는 기존 ComfyUI NAI 노드의 파서와 직렬화 규칙을 이식했고 원래의
GPL-3.0-only 파일 헤더를 유지합니다. 숫자 스코프·중첩·이스케이프 괄호·`artist:`를
처리하지만 모든 문법이 무손실로 변환되는 것은 아닙니다. 기존 규칙대로 ComfyUI의
명시 가중치 범위는 -5~5이고 범위 밖은 1.1로 대체되며, 잘못된 그룹은 제외될 수 있습니다.
구형 NAI는 1.05/0.95 배수로 근사하고 0·음수는 `[태그]`로 대체합니다.
구형 NAI 파싱은 소수 둘째 자리 반올림을 사용하며 미리보기에 이 한계를 표시합니다.
HTTP 변환은 32,768자·중첩 64단계로 제한하고 결과 길이와 유한 가중치를 검사합니다.
`POST /api/prompts/convert`의 필드는 `source`, `target`, `text`이고 문법 ID는
`comfyui`, `naiv4`, `oldnai`입니다. 같은 문법 간 변환은 거절합니다.

이번 캐릭터·문법 이식은 로컬 테스트와 mock 브라우저 검증입니다.
실제 NAI 다중 캐릭터 생성의 서버 수락·배치 품질·비용은 별도 라이브 검증이 필요합니다.

## 마스크 인페인트

1. 생성 방식을 **마스크 인페인트**로 바꿉니다. 모델 목록이 전용 인페인트 ID로 바뀝니다.
2. 입력 PNG/WebP/JPEG를 업로드하거나 **현재 결과를 입력 이미지로 사용**을 누릅니다.
3. 같은 크기의 마스크를 업로드하거나 캔버스에 수정 영역을 칠하고 **그린 마스크 저장**을 누릅니다.
   파일 마스크는 흰색이 수정 영역이고 검정은 보존 영역입니다. 화면에서는 수정 영역을 파란색으로 표시합니다.
   지우기와 비우기도 지원하며, 편집한 마스크는 다시 저장해야 전송할 수 있습니다.
4. 프롬프트·스텝·CFG·시드·강도와 전송 모델을 확인합니다. 입력 크기는 64의 배수여야 하고
   이미지·마스크·생성 크기가 모두 같아야 합니다. EXIF 회전은 화면에 표시된 방향으로 정규화합니다.
   빈 마스크와 자동 크기 변경은 허용하지 않습니다.
5. 비용 발생을 허용하려면 **Opus 요청 한도 적용**을 직접 해제한 뒤 생성하기를 누릅니다.
   한도가 켜져 있으면 큐 등록과 전송 전에 거절하며, 가져오기는 이 한도를 자동으로 해제하지 않습니다.

2026-10-09 [NAI 웹의 실제 인페인트 모델 변환 함수](https://novelai.net/_next/static/chunks/pages/_app-b1c0ffe38c343809.js)
(`63509.tM`)를 확인했습니다. V5 Curated에서 새 인페인트로 전환하면
`nai-diffusion-4-5-curated-inpainting`, V5 Full은 `nai-diffusion-5-full-inpainting`을 선택합니다.
V5 Curated 전용 ID는 웹 enum에 있지만 현재 실행 변환 함수는 사용하지 않으므로 실행 목록에서 제외합니다.
메타데이터 가져오기는 이 변환으로 원본 모델을 임의 변경하지 않고 원본 ID를 표시합니다.
V4 Curated Preview는 `nai-diffusion-4-curated-inpainting`입니다. V3의 인페인트 강도는 1만 지원합니다.
V4 이상의 1 미만 강도는 웹과 같이 `parameters.img2img.strength`로 전송합니다.
설정 이름과 마스크 동작은 [공식 인페인트 안내](https://docs.novelai.net/en/image/inpaint/)를 참고했습니다.

전체 크기의 일반 마스크 인페인트와 작은 영역의 Focused 보정 경로를 모두 지원합니다.
일반 인페인트는 Opus 보호에서 계속 차단하며, Focused 자격 확인도 실제 무차감 검증을 뜻하지 않습니다.

API는 기존 `POST /api/jobs` 또는 `/api/generate`에 `provider: "novelai"`, `operation: "infill"`,
`nai_model` 전용 모델 ID, `input_image`, `mask_image`, `inpaint_strength`, `nai_limit_opus_free: false`를 보냅니다.
이미지 경로는 `/api/inputs/reference` 업로드가 반환한 `inputs/references/...` 또는 관리된
`outputs/images/...` 상대 경로여야 합니다. 절대 경로·상위 경로·심볼릭 링크는 거절합니다.
`dry_run: true`는 입력 검사와 manifest 기록만 수행하며 이미지 인코딩·외부 요청은 하지 않습니다.

마스크 밖 픽셀은 입력 이미지로 합성해 보존합니다. 원격 원본 PNG는 `remote_inpaint` 변형으로
바이트 그대로 별도 저장하고, 합성 결과는 `Software=Anima APP`와 복원 가능한 생성 조건을 기록합니다.
합성 결과를 NAI 서명 원본으로 표시하지 않습니다. Manifest에는 입력·마스크·원격 PNG·합성 PNG의
SHA-256과 모델·동작·강도·경로가 남고, 이미지 base64나 토큰은 저장하지 않습니다.

## 요청 한도와 비용

Img2Img·Vibe·Precise는 보호 모드에서 이미지 준비·인코딩·토큰 조회보다 먼저 차단됩니다.
일반 인페인트도 보호 모드에서 거절합니다. 자동 디테일러와 수동 Focused는 앱이 원본에서 계산한
작은 크롭에만 별도 보호 검사를 적용하며, 전체 이미지 크롭·참조·알 수 없는 필드·잘못된 입력은 차단합니다.

- 이미지 너비와 높이는 64의 배수이며 각 변은 64–2048픽셀입니다.
- 스텝은 1–50, CFG는 0–20, CFG rescale은 0–1, 시드는 0–4294967295입니다. 시드 0도 그대로 유지됩니다.
- Opus 요청 한도를 켜면 1,048,576픽셀과 28스텝 이하로 실제 전송값을 조정합니다. 요청값과 전송값은 manifest에 따로 기록됩니다.
- 한도 미적용 시 이미지 최대 크기는 1,572,864픽셀입니다.
- 각 HTTP 요청의 `n_samples`는 1입니다. 여러 장은 앱의 서버 큐로 순서대로 생성합니다.

Opus 요청 한도는 이제 **보호 모드**로 동작합니다. ComfyUI NAI 노드의
`validate_opus_free_request`와 계정 확인 조건을 이식했습니다. 매 생성 전송 직전
`https://image.novelai.net/user/subscription`을 읽어 `active: true`, 정수 `tier: 3`인
Opus 구독을 확인합니다. V5는 추가로 `usage.isNegative: false`와 정수
`usage.percent >= 2`를 요구합니다. 2% 기준은 기존 노드의 보수적 보호 기준이며
요청별 비용 계산식이 아닙니다. V4.5 이하 모델은 활성 Opus 확인만 필요합니다.
[공식 FAQ](https://docs.novelai.net/en/faq/)도 V5의 충전식 사용량 한도와
V4.5 이하 모델의 차이를 안내합니다.

구독 비활성·다른 등급·V5 잔여량 부족·누락/잘못된 값·조회 실패는 생성 전송을 차단합니다.
429 이후 한 번 재시도할 때도 다시 확인하며 계정 응답을 캐시해서 재사용하지 않습니다.
조회는 생성 큐에 들어간 뒤 실제 전송 직전에 수행하므로, 큐 등록 성공은 계정 확인 성공을 뜻하지 않습니다.
드라이런은 계정 조회를 하지 않고 manifest에 `novelai.opus_preflight.status: not_checked`를 남깁니다.
성공한 보호 요청은 `verified`와 구독 등급, V5 잔여량 등 허용한 필드만 저장합니다.
보호를 직접 해제한 요청은 `disabled`로 기록되고 구독 확인 없이 전송할 수 있습니다.
일반 인페인트는 보호 모드에서 계속 차단됩니다.

계정 조회 실패는 `nai_opus_check_failed`(503), Opus 자격 미확인은
`nai_opus_ineligible`(409), V5 잔여량 부족/미확인은 `nai_opus_v5_allowance_low`(409)입니다.
생성을 전송하지 않았으므로 이 오류의 `remote_outcome_unknown`은 `false`이며
Infinity 큐도 다음 작업을 자동 예약하지 않습니다. 원격 오류 본문과 토큰은 반환/저장하지 않습니다.

이 검사는 전송 직전 자격 확인이며 실제 잔액 차감을 측정하지 않습니다.
잠금은 이 앱의 Python 프로세스 안에서 공유되므로 별도 ComfyUI 프로세스나 NAI 웹의
동시 사용까지 직렬화하지는 않습니다. 확인 성공을 무과금 검증으로 해석하지 마세요.

## 큐, 정지와 불확실한 결과

일반 생성과 자동 큐는 같은 서버 큐를 사용합니다. 브라우저를 새로고침해도 같은 Python 프로세스에 남은 작업을 다시 추적할 수 있습니다. 서버 프로세스가 종료되면 메모리 큐는 사라지며 재시작 시 자동 재제출하지 않습니다. 종료 전에 전송된 원격 요청의 결과는 불확실할 수 있으므로, 계정/원격 상태를 확인하기 전에 같은 요청을 자동 반복하지 마세요.

전송 전 대기 작업은 정지할 수 있습니다. 이미 전송된 NovelAI 요청은 정지 버튼을 눌러도 완료·과금될 수 있습니다. 정지는 다음 자동 큐 예약을 막고, 도착한 이미지와 생성 정보는 저장합니다. 이 경우 히스토리에 정지 요청 후 결과를 보존했다는 경고가 표시됩니다. 원격 정지는 로컬 GPU의 interrupt를 호출하지 않습니다.

모든 NovelAI 생성은 계정 확인·전송·429 재시도를 하나의 프로세스 공용 잠금으로 직렬화합니다.
앞선 전송이 끝난 시각부터 최소 **2초**를 기다립니다. 실패도 간격에 포함되며 보호를 해제해도
같은 간격을 적용합니다. 잠금·간격·429 대기 중 정지는 다음 전송을 막습니다.

Timeout, 연결 오류, 서버 오류나 잘못된 이미지 응답은 코드와 정제된 메시지로 표시합니다. 결과가 확정되지 않으면 `remote_outcome_unknown: true`가 포함됩니다. 이 실패를 자동 재전송하지 않으며 Infinity 큐도 다음 작업을 예약하지 않습니다. HTTP 429에만 2–60초 대기 후 한 번 재시도합니다. `Retry-After`의 초 값과 HTTP 날짜 형식을 읽습니다.

## 저장과 검증

T2I 원격 PNG는 재인코딩하지 않고 검증한 원본 바이트를 저장합니다. 인페인트는 원본 응답과 마스크 합성 결과를 별도 저장합니다. Manifest에는 엔진, 모델, 실제 크기·스텝·시드, 요청/전송 설정, PNG SHA-256, 재시도 수와 와일드카드 확장 내역이 있습니다. 토큰·Authorization 헤더·민감한 원격 오류 본문은 저장하지 않습니다. 인증 필드를 HTTP 요청이나 프리셋에 넣으면 거절됩니다.

2026-10-09 앞선 T2I 검증은 V5 Curated 실제 생성 1건을 기록했습니다(`outputs/nai-live-20261009/report.json`).
이번 인페인트 확장은 mock transport와 브라우저 흐름으로 검증했으며 실제 NAI 인페인트 요청은 하지 않았습니다.
추가 Opus 보호와 요청 직렬화는 mock 계정 응답·가상 시계·스레드 동시성·브라우저로 검증합니다.
이 단계에서 실제 계정 조회나 이미지 생성 요청은 하지 않았습니다.
기존 실제 T2I 성공은 인페인트 모델 수락·보정 품질·계정 비용 검증이 아닙니다.
로컬 렌더링도 mock 회귀와 실제 GPU 생성 검증을 구분해야 합니다.

## Img2Img

생성 방식을 **입력 이미지 변형 (Img2Img)**으로 선택하고 입력 이미지를 업로드하거나 현재 결과를 사용합니다.
강도·추가 노이즈는 0–1이며 0도 그대로 유지합니다. 입력은 EXIF 방향을 정규화하고 흰색으로 투명도를 합성한 후
생성 크기로 Lanczos 리사이즈합니다. 마스크는 전송하지 않습니다. Opus 보호를 직접 해제해야 실행합니다.
API: `operation: "img2img"`, `input_image`, `img2img_strength`, `img2img_noise`.

## Vibe Transfer와 Precise Reference

**Vibe Transfer / Precise Reference** 패널에서 종류별 카드를 추가하고 이미지·강도·정보 추출량 또는 fidelity를 설정합니다.
각 종류 최대 16개이며 두 종류를 함께 사용할 수 없습니다. 설정·관리 파일 경로는 프리셋과 히스토리에 복원됩니다.
메타데이터에만 있는 참조 인코딩/이미지는 가져오지 않으며 가져오기 시 이전 참조 카드를 지웁니다.

| 기능 | 지원 모델·방식 | 준비·비용 |
|---|---|---|
| Vibe | V3 / Furry V3 / V4 / V4.5. V4/V4.5 인페인트·디테일러 제외 | V3는 448×448 검정 letterbox 이미지 전송. V4/V4.5는 encode-vibe 후 생성 |
| Precise | V4.5 Curated / Full, 일반 생성·Img2Img·인페인트·디테일러 | character, style, character&style. 가까운 화면 비율의 1024×1536 / 1536×1024 / 1472×1472 검정 letterbox |

V4/V4.5 Vibe는 모델·정규화한 이미지·정보 추출량으로 `outputs/nai-vibe-cache`에 인코딩을 저장합니다.
강도만 변경하면 재인코딩하지 않습니다. 정보 추출량·모델·이미지를 바꾸면 새 인코딩이 필요합니다.
정규화를 켜면 강도 절댓값의 합이 1을 넘을 때 1 이하로 조정합니다. 캐시에는 체크섬을 기록하며,
손상된 캐시는 자동 재인코딩하지 않습니다. 저장 가능 여부를 확인한 뒤 인코딩을 요청합니다.
강도 0인 카드는 전송에서 제외하지만, 보호 모드를 우회하는 용도로 사용할 수 없습니다.

[공식 Vibe 안내](https://docs.novelai.net/en/image/vibetransfer/)는 인코딩과 여러 참조의 추가 비용을 설명하며,
[Precise 안내](https://docs.novelai.net/en/image/precisereference/)는 참조 유형과 Vibe 동시 사용 제한을 설명합니다.
앱은 비용을 확정해서 계산하지 않습니다. API 필드는 `nai_vibes`, `nai_references`, `nai_normalize_vibe_strengths`입니다.

## 자동 디테일러와 WD 캐릭터 매칭

생성 후 **생성 후 자동 디테일러**를 켜거나, 생성 방식을 **기존 이미지 자동 디테일러**로 선택합니다.
후자는 기존 입력에서 보정 크롭만 전송하며 T2I를 먼저 실행하지 않습니다. `nai_detailer.enabled: true`를 사용합니다.
얼굴·눈·손, 첫 / 모든 영역, 최대 영역 수, 마스크 임계값, 크롭·패딩·팽창 / 수축, 강도·스텝을 설정합니다.
검출은 YOLO + SAM B 또는 SAM3이며, 눈은 같은 얼굴에 묶습니다. SAM3의 텍스트별 마스크도 개별 영역으로 계획합니다.

공통 모드에서는 공통 프롬프트와 캐릭터 최대 1명을 사용합니다. 여러 캐릭터는 WD 매칭을 선택합니다.
WD는 원래 캐릭터 프롬프트에 있는 식별 특징을 비교하며, 이름·가중치·프랜차이즈·네거티브 원문을 유지합니다.
공통 특징과 낮은 점수 / 작은 점수 차는 매칭 근거로 쓰지 않으며, 불확실한 영역은 한 차례 좁은 문맥으로 재확인 후 보류합니다.
캐릭터 순서로 강제 배정하거나 태거 관찰 태그를 생성 프롬프트에 추가하지 않습니다. WD 장치와 배치 크기도 선택합니다.

각 보정은 고정된 원본을 입력으로 사용합니다. 32픽셀 마스크 박스 / 8픽셀 격자와 영역 소유권을 적용해
겹친 크롭이 다른 캐릭터를 덮지 않게 합니다. 크롭 원격 원본과 완료된 합성 체크포인트를 단계마다 저장합니다.
기본 생성 후 보정이 실패하면 기본 결과·완료된 크롭을 보존합니다. 기존 이미지 보정에서 일부 크롭이
완료된 뒤 실패해도 완료된 합성 결과를 표시하고 히스토리에 남깁니다. 원격 실패와 로컬 추론 오류 모두
경고와 `stop_scheduling: true`를 반환해
유한·무한 배치의 후속 생성을 멈춥니다. 미확정 원격 결과는 자동 재전송하지 않습니다.
결과 화면과 manifest의 `novelai.detailer`에 영역·매칭·상태·실제 크롭 크기·자격 확인을 남깁니다.

**영역·매칭 미리보기**는 기존 이미지에서 검출·매칭만 수행하며 토큰·계정 조회·원격 요청이 필요 없습니다.
생성 후 미리보기는 기본 생성 자체의 원격 요청은 실행합니다. `dry_run`은 이미지 경로와 요청을 검사하고 manifest만 작성합니다.

모델 준비:

```bash
python -m pip install '.[face-detailer,wd-matching]'
```

- `models/detectors`: `face_yolov8n.pt` 또는 `face_yolov8m.pt`, `full_eyes_detect_v1.pt`, `sam_b.pt` 또는 `sam_vit_b_01ec64.pth`.
- 손 YOLO를 켜면 `hand_yolov8n.pt` 또는 `hand_yolov8s.pt`도 필요합니다.
- YOLO + SAM B는 Ultralytics의 `YOLO`와 `SAM` 실행 클래스가 필요합니다.
  `.pth` 가중치는 추가로 `segment-anything`의 `vit_b` 모델과 `SamPredictor`가 필요합니다.
  실행 클래스가 누락되면 `sam_b_runtime_unavailable`로 기본 생성 전에 차단합니다.
  `.pt` SAM에는 RGB PIL 이미지, `.pth` SAM에는 RGB 배열을 전달합니다.
- SAM3는 `sam3.pt`, SAM3 지원 Ultralytics 및 **호출 가능한 텍스트 토크나이저를 제공하는 Ultralytics CLIP**이 필요합니다.
  `python -m pip install '.[sam3]'`로 선택 의존성을 준비합니다. 모델 가중치는 별도로 준비하며 자동으로 내려받지 않습니다.
  실행 클래스나 토크나이저가 누락되거나 호환되지 않으면 `sam3_runtime_unavailable`로 기본 생성 전에 차단합니다.
  SAM3에는 RGB PIL 이미지를 전달하며, 얼굴·눈·손은 각각 `face` / `eye` / `hand`로 검출합니다.
- 로컬 검출기 원본은 기존 `ANIMA_APP_FACE_DETECTOR_SOURCE` / `ANIMA_APP_FACE_DETECTOR_FALLBACKS`로 읽을 수 있습니다.
- WD는 `SmilingWolf/wd-vit-tagger-v3`, revision `7f6b584d0bd3f55c4531f14ba3d4761b2bccdc0f`의
  `config.json`, `selected_tags.csv`, `model.safetensors`를 Hugging Face 캐시 형식의 `models/rs_wd_tagger`에 준비합니다.
  기존 캐시는 `ANIMA_APP_WD_TAGGER_SOURCE`로 지정합니다. 런타임은 자동 다운로드 없이 로컬 파일만 읽습니다.

실제 요청 전 검출기·WD 의존성과 파일을 확인하므로 누락 상태에서는 기본 생성도 제출하지 않습니다.
실제 로컬 추론 검증은 CPU의 YOLO 얼굴·눈 / SAM B / WD와 SAM3 경로입니다.
SAM3는 기존 검출 미리보기 이미지 한 장과 기존 가중치에서 얼굴 1개·눈 2개·손 2개를 검출하고
눈을 얼굴에 묶는 것까지 확인했습니다. 별도 임시 런타임(Ultralytics 8.4.0 + Ultralytics CLIP)에서 실행했으며,
현재 앱 가상환경에 SAM3 런타임이 설치됐다는 뜻은 아닙니다. 여러 이미지의 정확도·GPU 실행·실제 NAI 보정 품질은 미검증입니다.
SAM3 증거는 `outputs/all-nai-port-20261009/sam3/native/report.json`에 있습니다.
손 YOLO n/s와 SAM B `.pt` / `.pth`의 실제 오프라인 CPU 추론도 같은 기존 이미지 한 장에서 확인했습니다.
각 조합에서 손 1개와 비어 있지 않은 SAM 마스크를 얻었으며, 얼굴·눈·손 동시 선택에서는 눈이 얼굴에
합쳐지고 손이 별도 영역으로 유지됐습니다. 기존 ComfyUI Python 환경과 가중치를 읽어 실행했습니다.
현재 앱 가상환경에는 Ultralytics / segment-anything이 설치되지 않았습니다. 여러 이미지의 검출 정확도와
GPU 실행은 미검증입니다. 증거는 `outputs/all-nai-port-20261009/hands/native/report.json`에 있습니다.

## 수동 Focused Inpainting

생성 방식을 **Focused Inpainting**으로 선택하고 원본과 작은 마스크를 지정합니다.
마스크 범위에서 크롭을 계산해 확대·보정하고 원본에 합성합니다. 검정 마스크 픽셀은 원본과 동일하게 보존합니다.
API: `operation: "focused_infill"`과 전용 인페인트 모델, `input_image`, `mask_image`, `nai_detailer`의 크롭·강도·스텝 설정.
보호 모드에서는 원본보다 작은 크롭, 각 축 최대 1024, 1,048,576픽셀·28스텝·1장 이하와 유효한 입력 / 마스크를 요구합니다.
내부 크롭 context만 예외를 사용할 수 있으며 HTTP boolean으로 일반 인페인트 차단을 우회할 수 없습니다.
각 실제 크롭 전송 전에 활성 Opus와 해당 모델의 잔여량을 확인하고 기존 잠금·2초 간격을 적용합니다.
각 보정 응답과 합성 이미지·누적 마스크를 저장합니다. 합성 이미지와 마스크가 모두 저장된 단계만 완료 결과로 취급합니다.
후속 단계에서 저장 실패·타임아웃·정지가 발생하면 마지막 완료 결과를 표시하고 후속 큐를 중단합니다.
응답은 받았지만 합성 저장에 실패한 경우 원격 결과 PNG를 보존하고 자동 재전송하지 않습니다.
이미 전송된 요청을 기다리던 중 정지하면 도착한 결과까지 저장하며, 다음 크롭은 전송하지 않습니다.
기록에는 크롭마다 실제 인페인트 모델·스텝·시드·응답 해시·구독 확인 요약과 완료/실패/취소 상태가 남습니다.
[공식 Focused 안내](https://docs.novelai.net/en/image/inpaint/)를 참고하되 현재 앱 경로의 라이브 수락·차감량은 미검증입니다.

남은 노드 기능 이식은 로컬 단위 / 큐 / mock 브라우저, 실제 로컬 검출·WD 추론으로 검증했습니다.
원격 Img2Img·Vibe 인코딩·Precise·Focused / 디테일러의 서버 수락·보정 품질·계정 차감은 별도 라이브 검증입니다.
