# 첫 설정과 이미지 생성 UX 벤치마킹

조사일: 2026-10-15 KST · 기준: Anima APP v0.6.0 / `05b363c`

## 결정 제안

처음 쓰는 사용자는 **연결하기 → 장면 입력 → 크기 선택 → 생성**만으로 첫 결과를 얻어야 한다. 이후 화풍·참조 그림·얼굴 보정·작업 순서를 추가한다. 모델 준비와 계정 연결은 한곳에서 처리하고, 선택한 작업에 필요한 설정만 보여준다.

첫 개선 순서는 **연결/준비 화면 → 간단한 생성 화면 → 그림에서 시작 → 보정 단계 통합**이다. 기존 고급 설정과 프롬프트 원문, 프리셋, 생성 이력은 유지한다.

- [클릭 가능한 화면 설계안](ui-setup-concept.html): 생성 설정, 준비 안내, 이미지의 사용 목적, 고급 설정 전환. 실제 연결·검색·생성은 하지 않는 시안이다.
- [기존 라이브러리/UI 벤치마킹](LIBRARY_BENCHMARK_2026-10-14_KO.md)

## 조사 범위와 근거 수준

이번 비교는 UX 검토다. 경쟁 서비스의 생성 속도·비용·그림 품질을 측정한 실험이나 초보 사용자 테스트는 아니다.

| 대상 | 확인한 근거 | 범위 |
|---|---|---|
| Anima APP | 실행 중인 앱의 화면/DOM + v0.6.0 소스 | 현재 화면과 입력 구조 확인. 실제 생성은 하지 않음 |
| PixAI | 공개 생성 화면/DOM, 이미지 검색 진입 화면, 공식 가이드 | 로그인 전 화면 및 문서. 개인 이미지 업로드·생성 없음 |
| Leonardo.Ai | 공식 최신 생성 안내 | 실제 앱 접근은 로그인 화면까지. 로그인 이후 기능은 문서 근거 |
| Midjourney | 공식 Creating on Web, 공식 설정 화면 이미지 | 문서와 제공 스크린샷. 계정 내 생성 화면 직접 조작 아님 |

| NovelAI | 공식 생성 기초·샘플러 안내 | 문서 근거. 아니마의 NAI 입력 구조와 함께 비교 |

로컬 관찰 자료는 `outputs/setup-ux-benchmark-20261015/`에 보관하며 공개 문서에 개인 라이브러리나 경쟁 사이트 이미지 파일을 포함하지 않는다. 서비스 UI와 문서가 다른 경우 관찰한 화면과 문서상의 설명을 구분한다.

## VRS에 직접 대응하는 비교 사례

PixAI는 2026-07-24 공식 안내에서 **이미지 업로드 → 같은/유사한 공개 작품 → 작품의 프롬프트·모델·LoRA 확인 → 생성 화면으로 이동**을 설명한다. [공식 발표](https://pixai.art/en/news/2037346180395618613), [이미지 검색](https://pixai.art/en/search/image).

아니마의 기존 방향과 매우 가깝다. 따라서 이미지 검색 후 생성 기록으로 연결되는 흐름 자체를 독자 기능으로 표현하지 않는다. 아니마에서는 개인 로컬 자료, 실제 기록의 작가 순서·가중치 보존, NAI↔Anima 변환, 양방향 보정 순서를 한 작업으로 이어 주는 데 집중한다.

그림을 넣었을 때 선택지는 세 가지로 구분한다.

1. **비슷한 그림 찾기**: VRS 사례 검색 → 사례 선택 → 작가 조합/프롬프트 선택 → 작성창 적용. 검색 그림을 생성 참조로 자동 전송하지 않는다.
2. **이 그림을 참고해 생성**: 현재 엔진에서 지원하는 이미지 입력 방식과 참조 범위를 선택한다. 엔진마다 가능한 참조 기능이 다르므로 동일 기능으로 표시하지 않는다.
3. **생성 조건 가져오기**: 이미지에 실제로 남아 있는 생성 기록을 읽고 적용 범위를 선택한다. 기록이 없을 때는 누락으로 표시한다.

사례 선택에서는 `작가 조합만` / `프롬프트` / `전체 조건`을 제공하고 적용된 출처를 작은 카드로 유지한다. 입력 그림에서 추정한 태그와 저장된 실제 프롬프트는 구별한다.

## 제안 화면과 동작

### 처음 실행: 무엇부터 할지 선택

`NovelAI로 생성` / `내 PC에서 Anima 생성` / `이미지부터 관리` 세 가지 입구를 제공한다.

- NovelAI: 토큰 입력 → 연결 확인 → 생성. 로컬 모델 준비를 강제하지 않는다.
- Anima: 기존 모델 확인 → 필요한 파일과 용량 안내 → 준비 → 생성. 토큰 입력을 강제하지 않는다.
- 이미지 관리: 폴더 등록·메타데이터 보기부터 시작. 유사 검색용 임베딩 모델 준비와 색인 진행은 그 기능을 선택한 때 안내한다.
- 두 엔진을 연결한 작업을 선택하면 해당 작업에 필요한 엔진·모델만 함께 검사한다.

현재 준비 API는 재사용할 수 있으나, 새로운 토큰 입력 API와 준비 화면은 구현이 필요하다. `토큰 있음`과 `인증 확인됨`을 구분한다. 토큰은 브라우저 초안·localStorage·생성 manifest·로그에 넣지 않는다. 기본은 서버 실행 동안 사용하고, 지속 저장을 제공한다면 운영체제 자격증명 저장소 등 별도 설계가 필요하다. 기존 환경변수 사용은 지원한다.

### 매일 쓰는 생성 화면

상단: `생성` · `이미지 작업실` · `연결·모델` · 언어.

기본 화면은 아래 다섯 그룹으로 제한한다.

1. **그릴 장면**: 프롬프트와 예시 넣기. NAI↔Anima 표기는 자동 변환 상태로 요약.
2. **화풍**: 저장한 작가 조합 또는 VRS에서 찾은 사례를 그림으로 선택. 선택 없음도 정상 상태.
3. **그림 크기**: 세로 / 정사각 / 가로. 선택 결과의 실제 픽셀 수는 작게 표시하고 직접 입력도 가능.
4. **생성 방식**: 사용자가 선택한 엔진·모델을 한 카드에 표시. 상세 모델/기본값 변경은 펼침.
5. **마무리**: 보정 없음 / 얼굴 보정 / 크게 만들기. 추가한 기능의 간단한 설정만 표시.

`고급 설정`에는 CFG, steps, sampler/scheduler, seed, 네거티브, LoRA, 메모리, 검출/크롭, 직접 단계 편집을 유지한다. 고급 값이 기본값과 다르면 `직접 설정`으로 표시한다. 간단/고급 보기 전환은 값과 원문을 바꾸지 않는다.

`추천 설정`은 엔진·모델별 검증된 설정 묶음이다. 한 숫자를 모든 모델에 공통 적용하지 않고, 기존 프리셋을 불러온 뒤 자동으로 덮어쓰지 않는다. 스타일 선택도 프롬프트 원문과 참조 출처를 유지한다.

### 작업 순서와 실행 전 요약

기본 화면: `NAI 생성 → Anima 얼굴 보정` 같은 짧은 단계 칩으로 표시한다. 단계 선택 시 그 단계만 편집한다. 전문적인 순서 편집기는 필요할 때 펼친다.

실행 버튼 옆에는 엔진, 모델, 크기, 장수, 보정 단계, 준비 문제를 표시한다. NAI 보호 설정과 유료 실행 가능성은 현재 검증 가능한 범위로 표시하며, 근거 없이 `무료`라고 단정하지 않는다. 준비가 안 되면 `생성 불가`만 보여주지 않고 바로 `NovelAI 연결` 또는 `모델 준비` 동작을 제공한다.

NAI 무료 보호와 Anima 메모리 조정은 기존 서버 검사를 유지한다. 자동 조정이 생기면 적용값을 실행 요약에서 확인할 수 있게 한다. 모델 다운로드 완료와 실제 생성 가능 여부도 구별한다.

### 생성 다음 작업

결과 아래에 `다시 생성` / `얼굴 보정` / `크게 만들기` / `비슷한 그림` / `조건 재사용`을 둔다. 선택한 결과를 입력으로 명시하고, 원본·보정본 및 출처 연결을 보존한다. 기술 설명 대신 지금 할 수 있는 동작을 보여준다.
