# 생성 작업실과 작업 순서

상단 **앱 언어**에서 영어·한국어·일본어를 전환합니다. 언어 선택은 브라우저에 저장되고 작업 초안과 생성 조건은 유지합니다. [언어 설정과 적용 범위](LOCALES.md).

메인 화면은 왼쪽 프롬프트·조건, 가운데 결과 그림, 오른쪽 최근 결과로 구성됩니다. 생성과 정지 버튼은 하단에 유지됩니다. 세부 설정을 접거나 최근 결과를 숨겨 그림에 더 많은 공간을 줄 수 있습니다. 상단의 이미지 작업실로 이동해 유사사례와 작가 조합을 찾은 뒤 생성 화면으로 돌아옵니다.

## 서로 다른 엔진 연결

1. 왼쪽 **작업 순서**를 펼칩니다.
2. **NAI → Anima** 또는 **Anima → NAI**를 누릅니다. 첫 생성 엔진과 다음 디테일러가 함께 설정됩니다.
3. 각 단계의 **단계 조건**에서 모델, 보정 스텝, 변경 강도, CFG, 검출 방식, 크롭 배율과 여백을 조정합니다.
4. **첫 단계 프롬프트 사용**을 해제하면 해당 단계에 별도의 프롬프트와 네거티브를 입력할 수 있습니다.
5. **단계 추가**로 Anima 디테일러, NAI 디테일러, Anima 업스케일을 추가하고 ↑/↓로 후처리 순서를 바꿉니다. 첫 생성 이후 최대 6개 후처리를 지원합니다.
6. **생성하기**를 누르면 앞 단계가 저장한 이미지가 다음 단계의 입력이 됩니다. 프리셋 저장·복원과 이력의 설정 불러오기에 작업 순서도 포함됩니다.

예: `NAI 생성 → Anima 업스케일 → Anima 디테일러 → NAI 디테일러`. 첫 단계는 생성 또는 기존 이미지 편집이고, 이후 단계만 위아래로 이동합니다. 빠른 방향 버튼은 기존 후처리 목록을 해당 방향의 디테일러 한 단계로 바꿉니다. **생성만**은 목록에 추가한 후처리를 지웁니다. 기존 참조 이미지·후처리 패널에서 켠 기능은 첫 단계에도 적용되므로 작업 순서의 첫 단계 표시를 확인하세요.

## 모델과 토큰

Anima 디테일러도 Anima 체크포인트, Qwen 텍스트 인코더, VAE가 필요합니다. 얼굴 검출 모델만으로는 생성·보정할 수 없습니다. 프로젝트의 `models` 아래에 모델을 준비하고 선택 의존성을 설치합니다.

```bash
python -m pip install -e '.[face-detailer]'
```

NAI 단계에는 서버 프로세스의 `NAI_ACCESS_TOKEN`이 필요합니다. 토큰은 프리셋·작업 순서·공유 파일에 넣지 않습니다. 설치와 모델 준비는 [사용 가이드](USER_GUIDE_KO.md), NAI 조건은 [NAI 제공자 문서](NOVELAI_PROVIDER.md)를 따릅니다.

**Opus 무료 범위 보호**는 NAI 후처리에도 기본으로 켜집니다. 작은 정면 얼굴 사진에서는 크롭이 원본 전체를 덮어 실행이 거절될 수 있습니다. 이때 크롭 범위와 여백을 줄여 주세요. 적절한 값은 대상 크기와 위치에 따라 다릅니다. 요청 제한을 통과했다는 것만으로 청구 내역이 검증된 것은 아닙니다.

## 결과 보존과 실패

- 각 단계의 이미지와 manifest를 별도로 보존하고, 결과 화면의 단계 비교에서 볼 수 있습니다.
- `outputs/workflows/<id>.json`에 단계 상태와 입력·출력 해시를 남깁니다. 최종 manifest에도 원래 생성 조건과 작업 순서가 기록됩니다.
- 후처리가 실패하면 앞서 완료한 결과를 반환하고 남은 단계를 중지합니다. 실행 중 원격 요청을 취소했더라도 이미 처리된 요청은 되돌릴 수 없습니다.
- 드라이런은 모든 단계의 조건을 검증하지만 이미지를 생성하거나 실제 GPU·NAI를 호출하지 않습니다.
- 실행 중 프로세스가 종료됐을 때 작업을 자동 재개하거나 실패한 유료 요청을 자동 재전송하지 않습니다.

## 따라하기와 검증

[상세 이미지 생성 가이드](IMAGE_GENERATION_KO.md)는 설치부터 첫 이미지, 양방향 디테일러, 결과 비교까지 설명합니다. **v0.6.1은 연결 · 준비에서 NAI 토큰을 입력합니다. [토큰 설정](NAI_TOKEN_SETUP.md).** 현재 검증 범위는 [릴리스 안내](RELEASE_0.6.1.md)를 참고하세요.

## 원문 보존 · 단계별 프롬프트 변환 · 참고 사례

프롬프트 아래 **입력 프롬프트 표기**의 기본값은 자동 감지입니다. NAI V4/V5 단계는 `0.85::artist:이름 ::`, Anima 단계는 `(@이름:0.85)` 형식으로 전달합니다. 묶음 가중치·이스케이프된 작가명 괄호·작가 순서를 보존하고, 원문은 작성창에 남습니다. NAI V3는 구형 중괄호 가중치로 근사하며 변환 경고를 보여 줍니다. 명시적인 가중치가 없는 괄호는 의미가 모호하므로 자동 감지에서 임의로 재해석하지 않습니다. 원본 표기를 직접 고르거나 **변환 안 함**으로 우회할 수 있습니다. 서로 다른 가중치 표기가 섞였거나 변환 중 태그가 사라질 조건이면 요청을 멈추고 오류를 표시합니다.

**단계별 전달 미리보기**는 선택한 생성·후처리 엔진 각각의 양성/음성 프롬프트, NAI 캐릭터 슬롯, 자동 인식 작가, 변환 경고를 표시합니다. 이미지는 생성하지 않습니다. 실제 실행에서는 와일드카드를 펼친 다음 변환하므로 와일드카드 선택 결과는 미리보기와 구분됩니다. 모든 단계는 최초 생성 전에 정적 검증하며, 실행 시 펼쳐진 프롬프트도 각 단계에서 다시 검증합니다.

작가 처리는 다음 규칙을 따릅니다.

- 이미 `artist:` 또는 `@`가 붙은 이름은 목록 포함 여부와 관계없이 명시적인 작가 태그로 처리합니다.
- 접두사가 없는 **태그 전체**만 로컬 단보루 작가 태그와 대조합니다. 공백/밑줄·대소문자·이스케이프된 괄호 차이를 정규화하고 정확히 일치할 때만 접두사를 붙입니다. 문장 일부, 접두 부분, 알려지지 않은 이름은 추측하지 않습니다. 별칭 해석과 흐릿한 일치는 지원하지 않습니다.
- 기본 수집 설정은 게시물 수순 활성 작가 태그를 최대 20,000개까지 조회합니다. **전체 작가 목록이 아닙니다.** 목록의 수량·수집일·일부 목록 여부를 미리보기에 표시합니다. 이미지나 계정 정보는 수집하지 않으며 생성 중에는 네트워크로 작가 이름을 조회하지 않습니다.
- 목록이 없거나 손상되면 접두사 자동 인식만 생략합니다. 명시적인 작가 표기 변환은 계속 동작합니다. 목록 파일은 Git 제외 경로 `outputs/artist-catalog/danbooru.json`에 보관합니다.

목록 재수집은 프로젝트 가상환경에서 명시적으로 실행합니다. 원자적 교체 전에 검증하므로 요청 실패 시 기존 목록이 남습니다. 429는 재시도하지 않습니다.

```bash
PYTHONPATH=src .venv/bin/python scripts/update_artist_catalog.py --pages 20 --interval 2
```

생성 폼의 프롬프트·제공자·작업 순서·가져온 참고 사례는 같은 브라우저·앱 주소에 자동 저장되고 새로고침 후 복원됩니다. **저장된 작업 불러오기 / 저장 초안 삭제**로 관리하며 복원이 생성 실행을 시작하지 않습니다. 이미지 업로드 파일 자체를 브라우저에 저장하지 않으므로 참조 경로는 서버에 남아 있어야 합니다. 파일 업로드 중이라면 완료 후 폼을 편집하고 저장 표시를 확인하세요. 라이브러리 편집 초안과 되돌리기 이력은 별도로 유지됩니다. 브라우저 저장소 삭제·시크릿 세션 종료·다른 주소에서는 복원되지 않을 수 있습니다.

라이브러리에서 가져온 **이미지 ID + 정확한 생성 기록 ID + 가져온 범위**를 생성 조건 및 manifest에 남깁니다. 생성 화면과 결과의 참고 사례 버튼으로 원래 기록을 다시 열고, 초안에서는 **연결 해제**할 수 있습니다. 이미지가 여러 생성 기록을 가진 경우에도 해당 기록을 선택합니다. 서버에 원본이 없어졌다면 찾지 못했다는 안내를 표시합니다. `authoring_request`는 편집 원문, `prompt_processing`은 실제 변환 기록, 최상위 `prompt`는 엔진에 전달된 문구입니다. 이 연결은 재사용 출처이며 작가의 실제 저작권·이미지의 제작자를 판정하는 기능이 아닙니다.

API는 기존 호출과 호환되며 `prompt_routing`을 생략하면 입력 원문을 유지합니다. 변환을 요청하려면 `{"prompt_routing":{"source":"auto"}}`를 추가하세요. `POST /api/prompts/plan`은 생성 요청과 같은 형태로 단계별 미리보기를 반환합니다. 프리셋과 생성 이력 복원은 저장된 작성 원문과 작업 순서를 우선 사용합니다.

이 추가 작업의 검증은 전체 회귀 1,112 통과·1 건너뜀, 생성 화면 10개·라이브러리 20개·연결성 8개 브라우저 시나리오입니다. 양방향 2단계/3단계 엔진 연결은 모의 제공자로 프롬프트·참고 사례 전달을 검증했습니다. 자동 변환 적용 후의 실제 NAI·GPU 재생성은 이번 검사에 포함하지 않습니다. 창을 띄우지 않는 Chromium으로 검사하고 종료했으며, 결과는 Git 제외 `outputs/usability-linkage-20261014/`에 보관합니다.
